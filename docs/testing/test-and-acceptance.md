## 1. 测试目标

测试不只验证页面“能打开”，而要证明以下核心承诺成立：

1. 教学内容、二维计算、三维结构和时间轴表达的是同一个计算步骤。
2. 预置 Trace 和真实模型 Trace 遵循同一数据契约。
3. 数值、形状、掩码、概率和采样结果在允许误差内正确。
4. 桌面、移动、低性能和能力降级环境都能完成对应学习路径。
5. 用户输入留在浏览器，真实模型不会在未确认时自动下载。
6. 键盘、减少动态效果、颜色替代和文本说明可用。
7. 三维渲染和模型推理满足明确性能、内存与恢复要求。

本文档定义测试范围、测试层次、验收矩阵、性能预算、缺陷等级和发布门槛。测试结果必须能够追踪到产品需求编号和实施工作包。

## 2. 质量原则

1. **领域正确性优先**：数值或步骤错误属于严重缺陷，即使界面看起来正常。
2. **确定性优先**：预置 Trace、随机采样和动画状态应能在测试中复现。
3. **测试用户行为**：组件测试通过角色、名称和实际交互验证，不依赖脆弱的内部结构。
4. **分层验证**：大量逻辑由快速单元测试覆盖，少量关键路径由真实浏览器覆盖。
5. **能力可降级**：无 WebGPU、无 WebGL2、模型失败都必须有明确且可测试的结果。
6. **失败可诊断**：断言要说明哪个需求、哪个步骤和哪个实体不一致。
7. **提交前本地验证**：自动化 CI 在得到单独确认前不修改；现阶段每个工作包在本地完成质量门槛并推送结果。

## 3. 测试范围

### 3.1 范围内

- Trace 类型、Schema、适配器和版本处理；
- Zustand Store、选择同步和时间状态机；
- 中文课程结构、课程动作与 Trace 引用；
- 二维 SVG 计算流程、矩阵、掩码和文本替代；
- 三维场景实体、选择、相机状态、资源释放和降级；
- 2D/3D/课程/时间轴联动；
- 响应式布局、触摸和键盘交互；
- LocalStorage 版本、恢复和损坏处理；
- 模型主动下载、进度、取消、缓存和错误；
- WebGPU/WASM 推理与 Trace 转换；
- 无障碍、视觉回归、性能和浏览器兼容；
- 生产构建和 GitHub Pages 静态路径。

### 3.2 第一阶段范围外

- 第三方浏览器、GPU 驱动或模型运行库自身的完整正确性；
- 模型训练质量、事实准确性或开放式对话质量；
- 服务端、数据库、账号和云同步；
- 未列入支持矩阵的旧浏览器；
- 任意外部模型的兼容性。

范围外不等于完全忽略。项目必须通过固定版本、适配器契约和少量集成用例验证自身依赖方式正确。

命名规则：

- 单元/组件：与实现文件相邻，使用 `*.test.ts(x)`。
- 端到端：按用户能力命名，使用 `*.spec.ts`。
- 测试标题包含行为和结果，必要时包含需求 ID。
- Fixture 使用教学语义命名，例如 `maskedAttentionTrace`，避免 `data1`。

示例：

```ts
it('FR-TIME-001：播放到最后一步后自动暂停', () => {})
```

## 6. 测试数据策略

### 6.1 Fixture 分级

| Fixture | 用途 | 特征 |
| --- | --- | --- |
| `minimalTrace` | 类型与 Store 单元测试 | 2 Token、3 步骤、最小合法字段 |
| `maskedAttentionTrace` | 2D 与掩码测试 | 4 Token、明确的上三角掩码 |
| `verticalSliceTrace` | M1 集成/E2E | Token→Attention→Output 完整路径 |
| `fullPresetTrace` | M2 完整课程 | 完整 Transformer 核心步骤 |
| `brokenTrace*` | 错误与迁移 | 缺字段、坏 ID、坏版本、NaN、越界 |
| `onnxGoldenTrace` | 真实适配器契约 | 固定模型 Revision 与固定输入 |

### 6.2 确定性要求

- 预置 Trace 固定版本和内容哈希。
- 采样测试固定 Seed、Temperature、Top-k、Top-p。
- 动画测试使用假计时器或直接定位最终状态。
- 时间相关断言避免依赖实际等待。
- 视觉测试关闭光标闪烁、随机噪声和非确定粒子。
- 三维截图固定视口、设备像素比、相机和光照参数。
- ONNX Golden 测试固定模型 Revision，不引用会变化的远端 `main`。

### 6.3 数值误差

不同浏览器后端可能存在浮点差异，断言使用分层容差：

| 数据 | 推荐误差 | 说明 |
| --- | --- | --- |
| Token ID、Shape、Mask | 精确相等 | 离散数据不得漂移 |
| 概率和 | `1 ± 1e-5` | JS 或 WASM 常规路径 |
| FP32 中间张量 | 绝对/相对 `1e-5` | 根据算子调整 |
| 量化模型输出 | 以 Golden Top-N 和排序为主 | 不要求逐元素等于 FP32 |
| 3D 坐标 | `1e-3` | 避免渲染浮点细差 |

任何放宽误差的用例必须解释原因，不使用巨大容差让错误通过。

## 7. 分层测试方案

### 7.1 L0｜类型与静态检查

每次提交执行：

```bash
npm run lint
npm run build
```

重点检查：

- `ModelTrace` 联合类型是否穷尽处理；
- Store Action 是否接受非法 ID 或索引；
- Worker 消息是否区分请求、进度、结果和错误；
- React Hook 依赖和资源清理；
- 未使用依赖、死代码和调试日志。

退出标准：零错误；警告必须被理解，不能长期积累未知警告。

### 7.2 L1｜领域单元测试

覆盖对象：

- Trace Schema 和迁移；
- 实体 ID 与交叉引用；
- Tensor 摘要；
- 因果掩码；
- Softmax、Temperature、Top-k、Top-p；
- Seed 随机数；
- 课程 Action 校验；
- 能力等级决策；
- LocalStorage 迁移与清理。

关键用例：

1. 未知 Trace Schema 版本被拒绝。
2. 步骤引用不存在的实体时返回可诊断错误。
3. Attention 上三角屏蔽位置不会得到可见概率。
4. Temperature 非法值不会产生 `NaN`。
5. Top-k 不大于词表大小，Top-p 保留至少一个候选。
6. 同 Seed 采样相同，不同 Seed 可产生允许差异。
7. 损坏本地数据回到默认值，不阻断启动。

### 7.3 L2｜适配器契约测试

对 `PresetTraceAdapter` 与 `OnnxTraceAdapter` 运行同一套契约：

- 返回可校验的 Schema 版本；
- Token 数量与张量对应维度一致；
- 每一步输入/输出引用存在；
- Layer 和 Head 索引合法；
- Logits 与概率指向有效 Tensor；
- Trace 步骤顺序可供课程和时间轴消费；
- 错误类型可映射为用户可行动提示；
- 取消后不再向 Store 写入就绪结果。

契约测试是防止“预置模式能用、真实模式另写一套界面”的主要质量门。

### 7.4 L3｜Store 与状态机测试

覆盖：

- 初始化 Trace；
- 首步/末步边界；
- 播放、暂停、速度和重置；
- 时间轴拖动；
- 模式切换；
- Token/Layer/Head/Entity 选择；
- 相机 guided/manual 状态；
- Trace 切换后的选择清理；
- reduced-motion 偏好；
- 异步加载的竞态和取消。

重点组合场景：

1. 播放过程中点击实体，按定义暂停或继续且所有视图一致。
2. 快速多次拖动时间轴，最终状态等于最后一次输入。
3. 旧模型请求晚于新请求返回，旧结果被丢弃。
4. 课程切换时相机处于手动模式，只有明确动作才恢复引导。

### 7.5 L4｜组件测试

组件测试关注用户可见行为：

- 工作台区域和中文标题可读；
- 时间轴按钮具备正确名称和禁用状态；
- 课程前后导航与深入内容；
- 2D 图形具备 SVG 标题、文字摘要和选中状态；
- 移动端标签正确切换内容；
- 错误边界提供重试和回到预置案例；
- 模型下载确认、进度、取消和失败提示；
- 焦点在弹窗打开、关闭后正确管理。

避免断言私有 Class 名和具体 DOM 层级。允许对设计 Token 和关键布局属性做少量契约断言。

### 7.6 L5｜2D 可视化测试

自动化检查：

- 节点数量、实体 ID 和当前高亮；
- Token 标签与 Trace 顺序；
- 矩阵行列与 Shape；
- Mask 单元标记；
- 连线起止实体；
- 不同 Token 数量下的 viewBox；
- 文字摘要与图形状态一致。

视觉检查：

- 标签不重叠或被裁切；
- 小数精度不过多；
- Q/K/V 色彩与图例一致；
- 暖白面板在浅色内容区可读；
- 200% 缩放时仍能完成核心操作。

### 7.7 L6｜3D 可视化测试

在 jsdom 中不测试真实 WebGL 像素结果，而分成：

1. 纯布局函数单元测试：实体位置、分组、LOD 和相机目标。
2. R3F 组件测试：场景树、实体属性和交互回调。
3. 真实浏览器测试：Canvas 初始化、点击/指针、相机和截图。

关键验证：

- 同一实体 ID 在 2D 与 3D 存在唯一映射；
- 选中实体具有颜色之外的轮廓、缩放或标签；
- 手动 Orbit 后相机模式为 manual；
- “返回讲解视角”恢复正确目标；
- unmount 后移除事件监听、动画帧和 GPU 资源；
- Context Lost 时显示提示并保留课程状态；
- 简化 3D 明确减少实体，不改变计算含义。

### 7.8 L7｜端到端测试

#### E2E-01｜首次引导学习（P0）

1. 打开应用。
2. 不触发模型下载。
3. 使用预置案例开始学习。
4. 依次完成 Token、Attention、Output。
5. 验证最终 Token、课程完成状态和进度保存。

覆盖：FR-LESSON-001、FR-TRACE-001、FR-TIME-001、FR-2D-001、FR-3D-001。

#### E2E-02｜时间轴控制（P0）

播放、暂停、前进、后退、重置和末尾停止；验证 2D/3D 标题与步骤一致。

#### E2E-03｜二维到三维联动（P0）

点击二维 Token/Attention 实体，验证三维选中、课程说明和 Store 调试状态或可见结果。

#### E2E-04｜三维到二维联动（P1）

点击三维实体，验证二维高亮、课程说明和返回讲解视角。

#### E2E-05｜移动端课程（P1）

360×800 视口完成核心 2D 路径，切换简化 3D，无页面横向溢出。

#### E2E-06｜能力降级（P1）

模拟 WebGL 不可用，验证 2D 安全模式、能力提示和课程连续性。

#### E2E-07｜进度恢复（P1）

学习到中间步骤后刷新，恢复有效进度；注入损坏数据后安全回到默认状态。

#### E2E-08｜真实模型生命周期（M3）

验证不自动下载、用户确认、进度、取消、重试、缓存命中和失败回到预置案例。

#### E2E-09｜网络隐私（M3）

拦截所有请求，断言用户输入不出现在 URL、请求头或请求体；仅允许固定的静态和模型资源请求。

### 7.9 L8｜视觉回归

基线场景：

- 1440×900 桌面初始页；
- Token、Attention、Output 三个关键步骤；
- 选中 Token 和 Head；
- 深入内容展开；
- 360×800 移动 2D；
- 简化 3D；
- 2D 安全模式；
- 加载、错误和空状态；
- reduced-motion 状态。

执行要求：

- 固定字体、视口、设备像素比和动画最终状态；
- 对 Canvas 允许小范围像素阈值，但 UI 区域保持严格；
- 每次基线更新必须人工查看差异；
- 视觉测试通过不替代可访问性或行为测试。

### 7.10 L9｜可访问性测试

自动化：

- axe 规则扫描；
- 可访问名称、角色、焦点和 `aria` 状态；
- 对比度计算；
- 页面缩放与文本溢出。

人工测试：

1. 只用键盘完成开始、课程、时间轴、2D 选择、视图切换和设置。
2. 检查焦点始终可见，弹窗焦点不逃逸。
3. 使用 NVDA + Chrome/Firefox 验证主要区域和状态通知。
4. 使用 VoiceOver + Safari 验证移动/桌面核心路径。
5. 开启减少动态效果，确认镜头和流向不产生长时间运动。
6. 使用常见色觉缺陷模拟，确认 Q/K/V 和状态仍可区分。

### 7.11 L10｜性能与内存测试

测试分为预置模式、完整 3D 和真实模型三类。

#### 预置模式预算

| 指标 | 目标 | 测试环境 |
| --- | --- | --- |
| 首次可交互 | ≤ 3 秒 | 中端笔记本、正常宽带、冷缓存 |
| 主线程长任务 | 单次尽量 < 50ms | 加载和章节切换 |
| 步骤切换响应 | ≤ 100ms 可见反馈 | Trace 已加载 |
| 初始模型网络请求 | 0 | 用户未确认真实模型 |

#### 三维预算

| 指标 | 桌面目标 | 移动目标 |
| --- | --- | --- |
| 稳态帧率 | 接近 60 FPS | 简化场景 ≥ 30 FPS |
| 交互最低帧率 | 不持续低于 30 FPS | 不持续低于 20 FPS |
| 场景对象 | 使用实例化与分组 | 使用更低 LOD |
| 资源释放 | 离开场景后不持续增长 | 同左 |

#### 真实模型预算

| 指标 | 目标 |
| --- | --- |
| 首次模型下载 | 约 100MB 内；超出需重新评估 |
| 下载取消反馈 | 1 秒内停止状态推进 |
| 推理输入 | 最多 12 Token |
| 主线程 | 推理不长时间阻塞 UI |
| 缓存 | 相同 Revision 不重复完整下载 |
| 内存 | 无持续增长；失败后可释放 Session |

性能失败不能只通过隐藏指标解决。必须说明用户可见影响，并在优化、降级或调整目标之间做明确决策。

### 7.12 L11｜模型正确性测试

真实模型模式至少验证：

1. 固定输入的 Token ID 与参考 Tokenizer 一致。
2. ONNX 最终 Logits 的 Top-N 与参考实现一致或满足量化误差标准。
3. 需要展示的中间张量确实来自模型输出或可验证计算。
4. Layer、Head 和维度顺序未在适配器中交换。
5. Attention Mask 与因果方向正确。
6. WebGPU 与 WASM 结果在约定误差内一致。
7. Trace 摘要标记 `sampleMethod`，用户不会把摘要误解为完整矩阵。
8. 模型切换或取消后不混用旧 Session 的结果。

Golden 数据生成过程、模型 Revision、依赖版本和哈希必须记录，确保结果可复现。

## 13. 缺陷等级与放行规则

### P0｜阻断

示例：

- 页面无法启动或主路径完全不可用；
- 教学数据或计算结论严重错误；
- 用户输入被意外上传；
- 模型在未确认时自动下载；
- 造成浏览器持续崩溃或设备明显失控。

规则：任何里程碑不得带 P0 放行。

### P1｜严重

示例：

- 2D/3D/课程状态不一致；
- 主流支持浏览器主路径失败；
- 键盘用户无法完成核心操作；
- 无 WebGL 环境无法进入 2D 回退；
- 模型取消或失败破坏预置课程。

规则：对应里程碑不得带 P1 放行，除非明确缩减范围并更新需求。

### P2｜一般

示例：

- 非核心布局在特定尺寸错位；
- 次要动效或状态文案不一致；
- 不阻断学习的性能波动。

规则：可以在有负责人、计划和用户影响说明时带入下一工作包，但正式发布前应收敛。

### P3｜轻微

示例：

- 极小视觉差异；
- 不影响理解的文案或间距问题；
- 非支持环境的轻微退化。

规则：进入常规待办，不阻塞里程碑。

## 16. 测试维护规则

- 修复缺陷时先添加能复现问题的测试，再修复实现。
- 需求变更时同步更新测试和追踪矩阵。
- 删除测试必须解释其覆盖如何被替代。
- 不使用大量 Snapshot 替代行为断言。
- 不把不稳定测试简单重试到“看起来通过”；先定位竞态和非确定来源。
- 外部模型网络测试与本地快速测试分开，避免日常验证被远端波动阻塞。
- 测试专用开关不得改变生产业务逻辑，只能提供观测和确定性控制。
- 覆盖率是发现盲区的工具，不作为唯一质量指标。

### 建议覆盖率门槛

| 范围 | 语句/行 | 分支 | 说明 |
| --- | --- | --- | --- |
| `domain/` | ≥ 90% | ≥ 85% | 核心计算和契约 |
| `store/` | ≥ 90% | ≥ 85% | 状态边界与竞态 |
| `adapters/` | ≥ 85% | ≥ 80% | 正常、错误和取消 |
| UI 组件 | ≥ 75% | ≥ 65% | 更重视行为与 E2E |
| 全项目 | ≥ 80% | ≥ 70% | 不为数字编写无意义测试 |

新模块低于目标时必须说明缺口，不应通过排除关键文件来美化数字。
