## 1. 交付范围

本工作包完成：

- 使用 Zustand Vanilla Store 建立课程、2D、3D 和时间轴共用状态；
- 管理 Trace 加载、当前步骤、播放速度、学习模式、当前视图、选择和相机模式；
- 实现带请求编号的 Trace 加载流程，忽略过期成功或失败结果；
- 实现 `goToStep`、`nextStep`、`previousStep`、`startPlayback`、`pausePlayback` 和 `resetPlayback`；
- 实现可释放、可替换调度器的播放控制器；
- 提供当前步骤、导航边界、当前实体和选中实体 Selector；
- 把预置 Trace 加载与播放控制器接入 React 应用生命周期；
- 把工作台学习模式、移动视图和底部时间线迁移到统一 Store；
- 将原静态时间线升级为 8 步真实进度、播放、暂停、前后导航和重置控件。

本工作包不实现结构化中文课程正文、真实 2D 数据图或 WebGL 3D 场景；三者分别属于 WP-14、WP-15 和 WP-16。

## 2. 状态契约

共享状态分为以下几组：

| 分组 | 核心状态 | 约束 |
| --- | --- | --- |
| Trace | `traceStatus`、`traceError`、`traceRequestId`、`trace` | 只有最新请求可以写入结果 |
| 导航 | `currentStepIndex`、`view`、`mode` | 步骤始终夹紧在 Trace 范围内 |
| 播放 | `playback`、`playbackRate` | 末步不能开始播放，到达末步自动暂停 |
| 选择 | Token、Layer、Head、Entity | 越界或不存在的实体不会污染状态 |
| 三维偏好 | `cameraMode`、`reducedMotion` | 重置回到引导相机，偏好可跨 Trace 保留 |

组件只能调用表达业务意图的 Action，不直接同时修改多个关联字段。步骤切换会同步更新第一项关联实体，避免后续 2D 和 3D 各自维护当前位置。

## 3. Trace 加载与竞态保护

加载流程使用单调递增的请求编号：

1. `beginTraceLoad` 返回当前请求编号并进入 `loading`；
2. `finishTraceLoad` 只接收编号仍匹配的结果；
3. `failTraceLoad` 只写入当前请求的错误；
4. `cancelTraceLoad` 使当前编号失效；
5. 组件卸载时同时取消 `AbortSignal`、失效请求并释放播放控制器。

这套规则可以处理 React Strict Mode 的挂载清理、未来案例切换以及较慢请求晚于较新请求返回的情况。

## 4. 播放状态机

播放计时器保存在独立控制器闭包中，不进入可序列化 Store：

```text
paused + startPlayback
  → playing
  → 等待当前 TraceStep.durationMs / playbackRate
  → advancePlayback
  → 下一步继续 playing
  → 末步自动 paused
```

任何手动步骤导航都会暂停自动播放。改变播放速度、切换 Trace 或改变步骤时，控制器先清理旧计时器，再按照新状态调度。`dispose` 会取消未触发计时器并解除订阅。

## 5. 时间线界面

时间线现在直接读取 Store，并提供：

- 当前步骤与总步骤，例如“步骤 02 / 08”；
- 当前步骤中文标题；
- 按 Trace 步骤数量生成的进度标记；
- 可用性随首尾边界变化的“上一步”和“下一步”；
- 动态切换名称与图标的“播放计算过程”和“暂停计算过程”；
- 回到首步、暂停并恢复引导相机的“重置”；
- `progressbar` 数值与中文 `aria-valuetext`。

移动端继续隐藏次要阶段标题但保留语义内容；桌面端显示阶段标题。控件保持至少 40px，主要工作台触摸目标继续保持 44px 基线。

## 8. 已知边界

1. 时间线当前支持按钮和自动播放，拖动或点击定位将在 WP-17 实现。
2. 课程、2D 和 3D 已共享步骤与选择契约，但当前视觉内容仍是静态教学预览。
3. 当前 Trace 很小，Selector 已按细粒度建立；3D 场景接入后还需用渲染计数与性能采样验证订阅范围。
4. 本工作包未把偏好写入 LocalStorage；版本化本地恢复属于 WP-18。
5. 本工作包未修改 CI；跨浏览器完整矩阵将在 M1 验收及发布阶段执行。
