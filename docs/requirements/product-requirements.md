# Transformer LayerScape｜产品需求文档

文档版本：1.0

发布日期：2026-07-24

文档状态：已确认，可进入实施

项目代号：LayerScape｜层境

## 1. 文档目的

本文档定义 Transformer LayerScape 第一阶段产品的用户、目标、功能范围、非功能要求和验收标准。它是产品设计、技术实施、测试验收和版本取舍的共同依据。

需求使用固定编号。实施提交、测试用例和缺陷记录应引用对应编号，例如 `FR-2D-001` 或 `NFR-PERF-001`，确保需求能够从文档追踪到代码和验证结果。

## 2. 产品概述

Transformer LayerScape 是一个运行在浏览器中的中文 Transformer 交互式教学工具。产品把一次 next-token prediction 同时表达为：

- 可逐步观察的二维计算流程；
- 可旋转、缩放和聚焦的三维模型空间；
- 与当前计算步骤同步的中文解释；
- 可播放、暂停、单步和拖动的统一时间轴。

产品不是模型训练平台，也不是聊天机器人。它的核心价值是让学习者在一个统一界面里建立“数据如何流过 Transformer，最后变成下一个 Token”的完整心智模型。

## 3. 背景与问题

现有 Transformer 学习材料通常存在以下割裂：

1. 图文教程容易解释概念，但难以呈现数据随时间和层级发生的变化。
2. 三维可视化容易展示模型规模，却可能弱化具体计算含义。
3. 二维流程图适合讲解矩阵运算，但难以建立完整模型结构感。
4. 英文术语、公式和代码同时出现时，中文初学者的认知负担较高。
5. 真实模型运行成本较高，首次访问等待时间长，容易阻断学习路径。

LayerScape 将二维、三维、时间轴和中文课程绑定到同一个 `ModelTrace`，使不同表达方式指向同一份计算事实。

## 4. 目标用户

### 4.1 核心用户

具备以下特征的中文学习者：

- 知道变量、函数、数组等基础编程概念；
- 听说过大语言模型，但不了解 Transformer 内部过程；
- 希望先形成直觉，再选择性理解公式和张量；
- 使用桌面浏览器学习，也可能通过手机复习。

### 4.2 次要用户

- 需要演示 Transformer 的教师或技术讲师；
- 希望快速复习 Attention 数据流的工程师；
- 对模型结构可视化感兴趣的非专业用户。

### 4.3 不作为第一阶段重点的用户

- 需要训练、微调或评测模型的研究人员；
- 需要导入任意私有模型的企业用户；
- 需要中文生成质量或完整聊天体验的终端用户。

## 5. 产品目标与成功标准

### 5.1 学习目标

完成默认课程后，用户应能够：

1. 说明文本如何变成 Token 和向量。
2. 说明 Q、K、V 在 Self-Attention 中分别承担什么作用。
3. 观察因果掩码如何阻止 Token 读取未来信息。
4. 说明 Residual、LayerNorm 和 MLP 位于数据流的什么位置。
5. 说明 Logits、Softmax、Temperature、Top-k 和 Top-p 如何影响采样。
6. 将二维计算视图中的当前元素对应到三维模型中的层、头和连接。

### 5.2 产品成功标准

第一阶段采用无需采集用户数据的本地验收指标：

- 新用户不下载真实模型，也能在 3 秒目标时间内开始预置课程。
- 用户能够从 Tokenization 连续走到 Output，并生成一个预置的下一个 Token。
- 任意课程步骤中，2D、3D、时间轴和解释文本指向同一 Trace 步骤。
- 桌面端完成同屏学习路径；移动端完成等价的 2D 学习路径并可查看简化 3D。
- 断网后，已加载的静态资源和已缓存内容按浏览器能力继续可用；无法使用的能力得到明确说明。

## 6. 产品原则

1. **先建立直觉，再展开细节**：默认使用通俗中文，公式、张量形状和伪代码放入“深入”层。
2. **同一事实，多种表达**：2D、3D、课程和时间轴必须读取同一状态，不允许各自维护不一致的教学数据。
3. **先可用，再下载**：预计算案例随站点发布；真实模型必须由用户主动触发下载。
4. **不以视觉牺牲理解**：动效只解释状态变化，不加入与学习无关的持续运动。
5. **隐私默认本地**：用户输入、推理和学习进度留在浏览器。
6. **渐进增强**：低性能设备仍能完成核心二维课程，高性能设备获得完整三维体验。

## 7. 用户旅程

### 7.1 首次进入

1. 用户打开首页，看到产品用途、预置示例和“开始学习”。
2. 系统进行 WebGL、WASM、内存和动效偏好检测。
3. 用户无需下载模型即可进入第一章。
4. 页面用一次短引导说明 2D、3D、时间轴和“深入”按钮的位置。

### 7.2 引导学习

1. 用户阅读当前步骤的中文解释。
2. 点击“下一步”或时间轴播放。
3. 2D 高亮具体计算，3D 聚焦对应结构。
4. 用户可以暂停、回退、拖动时间轴或旋转三维场景。
5. 用户手动移动相机后，可点击“返回讲解视角”恢复引导镜头。
6. 完成章节后，系统仅在本地记录进度。

### 7.3 自由探索

1. 用户从引导模式切换到自由探索。
2. 点击三维层、Attention Head 或二维算子。
3. 其他视图定位到相同实体并显示对应说明。
4. 用户切换 Block、Head、Token 或采样参数，观察结果变化。

### 7.4 真实模型实验

1. 用户主动选择“加载真实模型”。
2. 页面说明下载体积、仅本地运行和可能的设备限制。
3. 用户确认后开始下载，可查看进度并取消。
4. 加载成功后，用户输入短英文文本并运行推理。
5. 发生下载、内存或兼容性错误时，系统保留当前学习位置，并允许返回预置案例。

## 8. 功能需求

优先级说明：

- P0：第一阶段可用版本必须完成。
- P1：完整 MVP 必须完成，但不阻塞首个垂直切片。
- P2：后续增强项。

### 8.1 应用外壳与导航

#### FR-SHELL-001｜统一学习工作台（P0）

桌面端必须提供课程/2D 区域、3D 场景、顶部控制区和底部时间轴。

验收条件：

- 视口宽度不小于 1024px 时，2D 与 3D 同屏显示。
- 顶部可以切换引导学习和自由探索。
- 时间轴始终能够显示当前位置、总步骤和播放状态。

#### FR-SHELL-002｜移动端视图切换（P1）

移动端必须提供课程、2D 和 3D 的明确切换入口，不能简单压缩桌面布局。

验收条件：

- 360px 宽度下无横向页面溢出。
- 2D 核心课程完整可用。
- 3D 使用简化结构；不支持时提供文字和二维替代说明。

#### FR-SHELL-003｜能力状态提示（P1）

系统必须显示当前运行等级：完整 3D、简化 3D 或 2D 安全模式；真实推理还需显示 WebGPU 或 WASM 后端。

### 8.2 引导课程

#### FR-LESSON-001｜章节化课程（P0）

默认课程至少覆盖 Token、Attention 和 Output 三个首期章节，最终扩展到完整计算链。

验收条件：

- 每一步包含标题、通俗中文解释、目标 Trace ID 和前后导航。
- 课程动作能够驱动高亮、镜头和时间轴。
- 刷新页面后可从本地恢复最近有效步骤。

#### FR-LESSON-002｜深入内容（P1）

每个核心概念可以选择性显示公式、张量形状和伪代码。

验收条件：

- 展开或收起不会改变当前 Trace 步骤。
- 公式附近解释每个符号的含义。
- 伪代码以理解过程为目的，不伪装成可直接运行的生产代码。

#### FR-LESSON-003｜首次引导（P1）

首次使用时说明四个核心区域；用户可以跳过，且之后能从帮助入口重新打开。

### 8.3 统一时间轴

#### FR-TIME-001｜播放控制（P0）

时间轴必须支持播放、暂停、上一步、下一步和重置。

验收条件：

- 播放时各视图按照同一个步骤序列推进。
- 到达末尾后停止，不产生越界状态。
- 重置后回到当前章节的第一步。

#### FR-TIME-002｜拖动定位（P1）

用户可拖动或点击时间轴定位到合法步骤；定位过程中应避免重复执行昂贵计算。

#### FR-TIME-003｜速度控制（P2）

提供至少慢速、标准和快速三档演示速度，并遵循“减少动态效果”设置。

### 8.4 二维计算视图

#### FR-2D-001｜核心计算链（P0）

二维视图必须表达 Tokenization、Embedding、Attention 和 Output 的首期数据流。

验收条件：

- 当前算子、输入和输出有明确高亮。
- 显示当前张量名称与形状。
- Token 颜色在不同步骤保持一致。
- Masked Attention 明确区分可访问和被屏蔽位置。

#### FR-2D-002｜完整 Transformer 链（P1）

MVP 必须扩展到 Tokenization、Embedding、LayerNorm、Q/K/V、Masked Self-Attention、Residual、MLP、Logits、Softmax 和 Sampling。

#### FR-2D-003｜局部展开（P1）

默认展示整体流程，只对当前 Block、Head 或算子展开矩阵单元和详细连线，防止信息过载。

#### FR-2D-004｜文本替代（P1）

关键图形必须有可读的文字摘要，使屏幕阅读器用户或无 3D 环境用户能够理解当前步骤。

### 8.5 三维模型视图

#### FR-3D-001｜模型空间（P0）

三维场景必须展示 Token、Attention 和 Output 的结构关系，并能跟随时间轴聚焦。

验收条件：

- 可以旋转、缩放和查看结构标签。
- 当前实体与二维当前算子保持同步。
- 相机自动移动不剥夺用户的手动控制。
- 存在“返回讲解视角”操作。

#### FR-3D-002｜双向选择（P1）

点击三维实体必须更新二维详情、课程解释和选中状态；反向选择同样成立。

#### FR-3D-003｜分级细节（P1）

教学小模型可以展示独立单元；真实模型按距离、重要性和选中状态使用聚合、实例化与按需展开。

#### FR-3D-004｜上下文丢失恢复（P1）

WebGL Context 丢失时暂停场景，保留课程状态，尝试恢复；失败后切换到二维安全模式。

### 8.6 2D/3D 联动

#### FR-SYNC-001｜统一选择状态（P0）

Token、层、Block、Head、算子和时间步骤必须存储在统一状态中。

验收条件：

- 任一视图改变选择后，其他视图在同一渲染周期内得到一致状态。
- 不允许使用仅靠 DOM 查询或组件间临时事件维持的隐式同步。

#### FR-SYNC-002｜稳定实体标识（P0）

所有可交互实体必须使用稳定 ID，预置 Trace 与真实 Trace 对相同概念使用相同命名规则。

### 8.7 预置案例与 Trace

#### FR-TRACE-001｜开箱即用的预置案例（P0）

站点必须内置至少一个短英文输入的预计算 Trace，无需联网下载模型即可使用。

验收条件：

- Trace 通过运行时 Schema 或等效校验后才进入 Store。
- 数据缺失时显示明确错误并回到安全初始状态。
- 预置案例覆盖首个 Token→Attention→Output 垂直切片。

#### FR-TRACE-002｜统一适配器契约（P0）

预置案例和真实模型适配器必须输出统一 `ModelTrace`，视图组件不能读取模型专属格式。

#### FR-TRACE-003｜版本迁移（P1）

Trace 数据包含 Schema 版本。遇到不兼容版本时，系统不得静默解释错误数据。

### 8.8 参数实验

#### FR-EXP-001｜采样参数（P1）

用户可以调整随机种子、Temperature、Top-k 和 Top-p，并看到输出概率或采样结果的变化。

验收条件：

- 输入范围有明确限制和帮助文本。
- 相同输入、相同参数、相同种子产生可复现结果。
- 非法组合自动修正或阻止运行，并说明原因。

#### FR-EXP-002｜结构选择（P1）

用户可以选择 Transformer Block 和 Attention Head，2D/3D 同步展示所选结构。

#### FR-EXP-003｜输入保护（P1）

第一阶段真实模型输入限制为最多 12 个 Token；超出限制时在推理前提示并阻止或明确截断。

### 8.9 真实模型

#### FR-MODEL-001｜主动下载（P1）

真实模型不会自动下载。用户操作前必须看到预计体积、用途、隐私说明和取消入口。

#### FR-MODEL-002｜下载生命周期（P1）

模型加载必须展示等待、下载、初始化、就绪、取消和失败状态。

验收条件：

- 下载进度可感知。
- 用户可以取消未完成操作。
- 失败不会破坏预置课程。
- 缓存命中时无需重复下载完整模型。

#### FR-MODEL-003｜浏览器内推理（P1）

模型输入和推理只能在浏览器本地执行，不发送到项目自建服务器。

#### FR-MODEL-004｜内部状态输出（P1）

真实模型适配器必须能够提供教学需要的内部张量或其可视化摘要；只有最终 Logits 的普通生成模型不能冒充完整可解释 Trace。

### 8.10 本地进度与偏好

#### FR-LOCAL-001｜本地保存（P1）

保存最近章节、步骤、动效偏好和显示偏好。数据带版本号，损坏时安全重置。

#### FR-LOCAL-002｜清除本地数据（P1）

用户可以从设置中清除学习进度和缓存提示；模型缓存清理由浏览器能力决定并明确说明。

### 8.11 错误与恢复

#### FR-ERR-001｜视图隔离（P1）

2D、3D、课程和真实模型加载使用独立错误边界。单个区域失败不得让整个页面空白。

#### FR-ERR-002｜可行动错误信息（P1）

错误提示必须说明发生了什么、用户可以做什么、是否影响课程进度，不直接暴露无法理解的底层异常堆栈。

#### FR-ERR-003｜安全回退（P1）

WebGPU 失败时尝试 WASM；完整 3D 不可用时尝试简化 3D；仍不可用时进入 2D 安全模式。

## 9. 内容需求

### 9.1 语言

- 导航、控件、课程、错误和帮助内容使用简体中文。
- Attention、Token、Embedding、Logits 等术语首次出现时使用“中文解释 + 英文原词”。
- 不强行翻译已经形成通用认知的缩写，如 Q/K/V、MLP、Top-k。
- 示例输入第一阶段以短英文为主，避免把中文分词差异混入第一条学习主线。

### 9.2 内容结构

课程内容采用结构化配置或 MDX 管理，每个步骤至少包含：

- 稳定课程 ID；
- 标题和通俗解释；
- 对应 Trace 步骤或范围；
- 2D 高亮目标；
- 3D 聚焦目标；
- 可选的公式、形状和伪代码；
- 前置步骤与完成条件。

### 9.3 内容质量

- 一个步骤只引入一个主要概念。
- 对“像什么”的类比必须同时说明“不等于什么”。
- 数值示例必须与 Trace 数据一致。
- 公式、张量形状和视图标注必须使用相同维度顺序。

## 10. 非功能需求

### 10.1 性能

#### NFR-PERF-001｜首次可交互（P0）

在中端笔记本、正常宽带和缓存未命中条件下，预置课程目标 3 秒内可交互。模型资源不得阻塞首屏。

#### NFR-PERF-002｜帧率（P1）

- 中端桌面设备的首期三维场景目标接近 60 FPS。
- 移动端简化三维场景目标不低于 30 FPS。
- 拖动时间轴时不进行无节制的对象创建和昂贵推理。

#### NFR-PERF-003｜模型体积（P1）

首选量化模型下载目标控制在约 100MB 内。超过目标必须记录原因并重新评估体验。

### 10.2 可访问性

#### NFR-A11Y-001｜键盘操作（P1）

导航、课程控制、时间轴、视图切换和关键实体选择能够通过键盘完成；焦点顺序与视觉顺序一致。

#### NFR-A11Y-002｜减少动态效果（P1）

遵循 `prefers-reduced-motion`。启用后取消非必要过渡，镜头移动改为即时或短距离变化。

#### NFR-A11Y-003｜颜色与文本（P1）

Q/K/V 和状态不能只靠颜色区分；文字与背景满足 WCAG 2.2 AA 的常规对比度目标。

### 10.3 兼容性

#### NFR-COMPAT-001｜浏览器（P1）

支持当前稳定版及其前一个主要版本的 Chrome、Edge、Firefox 和 Safari。WebGL2 为完整 3D 基线；WebGPU 只作为增强能力。

### 10.4 隐私与安全

#### NFR-PRIV-001｜不采集（P0）

第一阶段不接入账户、后端、云同步、广告、使用统计或第三方分析脚本。

#### NFR-PRIV-002｜输入本地化（P0）

用户输入不离开浏览器。若未来引入任何网络推理能力，必须作为新的产品边界重新确认，不能静默加入。

#### NFR-SEC-001｜内容边界（P1）

课程内容和模型输出按文本处理，不通过不受控 HTML 注入页面。外部模型和资源地址必须来自明确允许列表。

### 10.5 可维护性

#### NFR-MAINT-001｜类型与契约（P0）

核心 Trace、课程步骤、实体 ID 和 Store 状态使用严格 TypeScript 类型；适配器通过共享契约测试。

#### NFR-MAINT-002｜模块边界（P1）

渲染组件不直接负责模型下载或 ONNX 推理；课程内容不直接操作 Canvas 或 DOM。

## 11. 视觉与交互要求

产品采用“数字天文台”视觉方向：

- 三维区域使用深海军蓝背景，强调空间和结构。
- 二维课程面板使用偏暖的浅色表面，保证长文本阅读。
- Q、K、V、Residual、MLP 和 Output 使用稳定且色盲友好的语义色。
- 字体层级强调章节、步骤、当前张量和解释正文，不使用过多装饰性字体。
- 动效主要用于展示流向、选择变化和镜头聚焦。

所有色彩、间距、圆角、阴影、字体和动效时长应收敛为设计 Token，避免 2D 与 3D 成为两个割裂产品。

## 12. 数据与模型范围

### 12.1 预置教学数据

- 使用教学小模型或真实模型数据的受控摘要。
- 首个案例最多 12 个 Token。
- 数据包含 Token、层、Head、张量形状、部分矩阵值、注意力权重、Logits、概率和采样结果。
- 大矩阵可以保存降采样摘要，但必须标注摘要方式。

### 12.2 真实模型候选

第一阶段真实推理以 DistilGPT-2 结构为候选，并使用浏览器适用的量化 ONNX 资源。正式接入前必须完成：

1. 模型许可证与分发方式确认。
2. 实际下载体积和缓存行为验证。
3. 浏览器内存峰值测试。
4. 内部张量输出能力验证。
5. WebGPU 与 WASM 结果一致性抽样。

如普通模型文件不能输出教学需要的中间值，应导出经过插桩的 ONNX 图或提供可验证的中间状态计算，不能使用虚构数据填补真实模式。

## 15. 验收总表

| 验收主题 | M1 最低要求 | MVP 完成要求 |
| --- | --- | --- |
| 学习链路 | Token→Attention→Output 可连续完成 | 完整 next-token prediction 课程 |

| 2D | 当前算子、张量和流向可见 | 完整计算链与局部矩阵展开 |
| 3D | 可控制、可聚焦、与 2D 同步 | LOD、双向选择、恢复与降级 |

| 隐私 | 无分析、无后端、输入不上传 | 保持相同边界 |
| 测试 | 单元、组件、主路径 E2E | 跨浏览器、视觉、性能、无障碍 |

## 16. 需求变更规则

以下变化必须先修改本文档并重新确认，再进入代码：

- 引入后端、账户、统计或网络推理；
- 更换核心模型或显著增加下载体积；
- 改变主用户或学习目标；
- 删除二维或三维任一核心表达；
- 将桌面应用、原生应用或 VR 纳入当前版本；
- 修改隐私、许可证或外部资源分发边界。

普通文案修正、明确 Bug 修复和不改变验收语义的实现细节，不需要提升为产品范围变更，但仍应引用相关需求编号。
